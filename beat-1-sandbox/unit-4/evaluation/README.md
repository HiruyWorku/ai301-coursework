# Disclosed alternative Codex evaluation

The final Claude Sonnet evaluation was blocked by the account's individual spend limit. At the student's request, Codex CLI graded all 20 scored packages using the existing skill and the course's exact prompt template. The original course harness was not modified. This is an alternative evaluation; the course's Sonnet pass bar has not been validated for this model, and instructor approval for the substitution has not been obtained.

`../eval-run.txt` is generated by the alternative runner and labeled accordingly. `results.json` records model, CLI version, hashes, categories, and all five check grades per package. `responses/` contains the complete unedited final responses; `events/` contains the CLI event streams. Each package gets a fresh ephemeral session in an empty working directory, with tools forbidden. The runner validates that all five checks are present, the verdict follows the rubric, and no shell, web, or MCP tools were used. Gold labels are loaded for scoring only after all model responses have been saved. No rubric tuning is performed against the Codex results.

To reproduce with the supplied Unit 4 starter material and an authenticated Codex CLI:

```sh
python3 beat-1-sandbox/unit-4/evaluation/run_codex_eval.py \
  --harness /path/to/ai301-unit4-starter/eval/run_eval.py \
  --skill tools/pr-precheck \
  --output beat-1-sandbox/unit-4/evaluation
```

The runner uses gpt-6.1-sol with medium reasoning, matching the local Codex CLI's configured model and reasoning level at the time of this submission. CLI execution follows the [official Codex evaluation workflow](https://developers.openai.com/blog/eval-skills).

A separate Codex check of the real PR package is saved as `live-precheck.md`. It uses captured issue/thread/template and contribution instructions, the full three-dot branch diff, plan, PR draft, test evidence, and hosted CI results. It is explicitly an alternative to the blocked Claude live skill run.
